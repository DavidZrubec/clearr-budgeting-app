# Security Hardening Design — Clearr Budgeting App

**Date:** 2026-06-20
**App:** Capacitor + Supabase + Vercel budgeting app
**Approach:** Maximum security (defense in depth), with encrypted native storage instead of HttpOnly cookies

---

## 1. Session Security

### Current State
Session tokens (access + refresh) are stored in `@capacitor/preferences` (Android SharedPreferences / iOS UserDefaults) via a custom storage adapter in `src/supabase.js`. This is already more secure than localStorage — no changes to the storage backend.

### Improvements
- **Session encryption**: Wrap `@capacitor/preferences` storage with AES-GCM encryption using a device-derived key
  - On app launch, derive an encryption key using `crypto.subtle.deriveKey()` with PBKDF2 + a fixed salt (or device fingerprint)
  - Before calling `Preferences.set()`, encrypt the value with AES-GCM
  - Before returning from `Preferences.get()`, decrypt the value
  - Key lives only in memory — never written to disk
- **Files affected**: `src/supabase.js` — replace `capacitorStorage` implementation with `encryptedStorage`
- **No change to**: PKCE flow, auto-refresh, detectSessionInUrl, flowType

## 2. 2FA / MFA (TOTP)

### Overview
Use Supabase's native MFA APIs. Every user must enroll a TOTP authenticator app before accessing the app. This applies to both email/password and Google OAuth sign-ins.

### Flow

#### First-time enrollment (after signup or first login)
1. Check `supabase.auth.mfa.list()` — if no factors enrolled, redirect to enrollment
2. Call `supabase.auth.mfa.enroll({ factorType: 'totp' })` → returns QR code URL + secret + factor ID
3. Display QR code (rendered with `qrcode` library, inline) and manual setup key
4. User scans with authenticator app, enters 6-digit code
5. Call `supabase.auth.mfa.challenge({ factorId })` → returns `challengeId`
6. Call `supabase.auth.mfa.verify({ factorId, challengeId, code })` → factor is now active
7. Display recovery codes (10 codes, generated by Supabase) — user must confirm saved
8. Redirect to dashboard

#### Login with MFA
1. After `signInWithPassword()` or `signInWithIdToken()` (Google), Supabase returns `session` null + `weakPassword` null — MFA required
2. Call `supabase.auth.mfa.challenge({ factorId })` → user sees TOTP input
3. User enters code → `supabase.auth.mfa.verify({ factorId, challengeId, code })`
4. If valid → full session granted

### Files to create/modify
- **`public/styles.css`**: Add MFA screen styles
- **`public/script.js`**: MFA enrollment, challenge, recovery flows
- **`index.html`**: MFA screen divs

## 3. Rate Limits

### Layer 1 — Client-side Auth Backoff
- **Location**: `public/script.js` auth form submit handler (lines ~158-194)
- After 5 consecutive failures: disable submit button, show cooldown timer
- Backoff: 10s → 30s → 60s → 5min cap
- Resets on successful auth

### Layer 2 — Per-User DB Rate Limits
- **New migration**: `supabase/migrations/003_rate_limits.sql`
- **Table**: `rate_limit_log` (user_id, action, attempted_at)
- **Thresholds**: Auth login max 10/15min, password reset max 3/hour per user
- **Cleanup**: Delete rows older than 24h

### Layer 3 — API Endpoint Auth (see Section 4)

## 4. API Endpoint Authentication

| Endpoint | Auth Method |
|---|---|
| `api/budget-alerts.ts` | `x-vercel-cron: 1` header check |
| `api/recurring.ts` | `x-vercel-cron: 1` header check |
| `api/transaction-created.ts` | HMAC-SHA256 webhook signature verification |

**Vercel cron protection** (free, built-in):
```ts
if (req.headers.get('x-vercel-cron') !== '1') return new Response('Unauthorized', { status: 401 });
```

**Webhook HMAC verification**:
```ts
const signature = req.headers.get('x-supabase-webhook-signature');
const expected = createHmac('sha256', secret).update(body).digest('hex');
timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
```

### Files affected
- `api/budget-alerts.ts`, `api/recurring.ts`, `api/transaction-created.ts`
- `api/_lib/auth.ts` (new shared auth helpers)

## 5. Password Validation

- **HTML**: `minlength="8"`, `pattern` for complexity, password confirmation field
- **JS**: validate length ≥ 8, uppercase, lowercase, digit, special char, match confirmation
- **In-app password change**: verify current password first, then `auth.updateUser()`
- **Files**: `index.html`, `public/script.js`, `public/styles.css`

## 6. Email Verification Gate

- On bootstrap, check `user.email_confirmed_at`
- If not verified → show "verify email" screen with resend + refresh buttons
- Block access to dashboard until confirmed
- **Files**: `index.html`, `public/script.js`, `public/styles.css`

## 7. CSP Headers

Add to `vercel.json`:
```json
{
  "headers": [{
    "source": "/(.*)",
    "headers": [{
      "key": "Content-Security-Policy",
      "value": "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; connect-src 'self' https://sklbelglosyqxwdbfsij.supabase.co wss://sklbelglosyqxwdbfsij.supabase.co; img-src 'self' data: blob:; frame-src 'none'; base-uri 'self'; form-action 'self';"
    }]
  }]
}
```

## 9. Implementation Order

1. **Quick wins**: CSP headers, password validation, email verification gate, `.env` check
2. **API endpoint auth**: cron headers, webhook HMAC
3. **Session encryption**: encrypt tokens in Preferences
4. **Rate limits**: client backoff + DB table + middleware
5. **MFA / TOTP**: heaviest lift, highest impact
